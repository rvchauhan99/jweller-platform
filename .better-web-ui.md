## Design Context

### Users

Three audiences, three apps — never one skin.

1. **Shoppers** on the customer storefront (`{subdomain}.yourplatform.in` or custom domain). Mobile-first jewelry buyers. Job: trust this shop, find a piece, pay or start SIP on **this** jeweler’s gateway.
2. **Jeweler staff** on `admin.yourplatform.in` (owner, sales, inventory, accountant). Login with `tenant_code` + username. Job: POS, stock, online orders, SIP collections, GST — fast and dense.
3. **Platform operators** on `console.yourplatform.in`. Job: create tenants (including theme preview), watch provisioning, suspend, billing status.

### Brand Personality

Premium, precise, operationally serious.

- Storefront: luxury, calm, high trust (Cartier / Tanishq / Apple retail).
- Jeweler admin: fast, dense, unfancy (Stripe / Linear / Shopify Admin).
- Platform console: control and health (Vercel / Railway).

Language: clear and formal on the shop; short and operational in admin/console. No playful SaaS copy.

### Aesthetic Direction

- **Storefront:** large imagery, strong type, white space, quiet motion. Tenant CSS variables from `docs/THEMING.md` (`--color-primary`, fonts whitelist). No ERP tables.
- **Admin / console:** tables first, 8px tight rhythm, platform tokens. Tenant logo is orientation only — never restyle the ERP as `classic-gold`.
- **Anti-references:** generic four-card KPI dashboards, purple gradients, glassmorphism, card-in-card, Dribbble admin, global customer SSO UI, platform payment branding on checkout.
- **Theme:** storefront follows `site_theme` (no v1 shopper dark-mode toggle). Admin and console: light + dark.

### Implementation Defaults

Monorepo: `backend/` (FastAPI) + `frontend/` (Expo white-label + interim admin). See `docs/PROGRESS.md`.

| Layer | Default |
|-------|---------|
| Customer UI | Expo 54 + expo-router; theme from `/api/public/bootstrap` |
| Jeweler admin (interim) | Expo `/admin` with platform tokens |
| Jeweler admin (target) | Next.js + Tailwind + shadcn/Radix |
| Platform console (target) | Next.js control plane |
| API | FastAPI + Motor in `backend/` |
| Forms / tables (web admin target) | TanStack Form / TanStack Table |

Precedence: (1) `docs/FRONTEND.md` + `docs/THEMING.md` (2) this file (3) better-web-ui framework defaults.

### Design Principles

1. Three visual languages. Never ship a storefront that looks like an admin, or an admin that looks like a luxury brochure.
2. Hierarchy with type and spacing before color or cards. Color means status, metal, or tenant brand on the storefront only.
3. One obvious primary action per screen. Admin home is pending work (orders, SIP due, low stock), then metrics.
4. Brand tokens are CSS variables. Forbidden for brand: `text-blue-600`, `#C9A227`, hardcoded fonts.
5. Every reusable component has loading, empty, error, and an accessible keyboard path.
